## 怎麼重現素材（不要靠行銷文案猜 UI）

`/support` 內嵌 10 段示範短片，由頁面 JS 掛載：

```
https://storage.googleapis.com/voinance-guide/guide/<key>.mp4          # 短片
https://storage.googleapis.com/voinance-guide/guide/posters/<key>.jpg  # 海報（單格）
key = voice-basic | voice-multi | voice-date | voice-newcat | voice-recurring
    | history-backfill | reports-range | announcement | wish-pool | bug-report
```

- 海報圖是 **1180×2556** 的 JPEG（iPhone 14 Pro 尺寸，3× → 邏輯寬 393pt），所以
  「圖上 px ÷ 3 ≈ pt」。
- 海報多半停在**錄音中的模糊狀態**，資訊量低。真正的 UI 要看短片：
  **先用瀏覽器（Chromium 可解 H.264）seek 到指定秒數並停住**，再截圖。
  Playwright 內建的 ffmpeg 是 `--disable-everything` 的精簡版（只有 vp8／mjpeg），
  **不能解這些 mp4**，別浪費時間。
- 本輪的素材落在 `.freebuff/voinance/`（clips／posters／home.html／support.html／
  p-release-notes.html／p-known-issues.html／releases.json）與 `tmp/vref/`。兩者都在 .gitignore 內。
- 純文字頁面（`/release-notes`、`/support` FAQ、首頁功能清單）用 `read_url` 就夠。
  **但 `/release-notes` 的 HTML 是空殼**：9 版內容由前端 `fetch('/releases')` 渲染，
  所以要看全部版本得直接抓那支 JSON（我用 `node -e "fetch(...)"` 抓，存成 `releases.json`）。
- **看海報細節**：檢視頁 `tmp/vref/zoom.html?k=<key>&z=<顯示寬px>&y=<scrollTop>`，
  配 `preview_screenshot`。本 thread 的 preview viewport 實測只有 **361×631**，所以
  `z=361` ＝ fit-width（1180px 原圖 → 30.6% 縮放；592px 的兩張 → 61%，相當清楚）。
  想要 1:1 就設 `z=1180`，但一次只看得到約 30% 寬度，得左右分段看。
- 素材要重抓的話：海報 `posters/<key>.jpg`、短片 `guide/<key>.mp4`，同在
  `https://storage.googleapis.com/voinance-guide/guide/` 底下。
- `preview_navigate` 只接受 loopback，**不能直接連外站**；外站內容一律先抓成檔案
  再由 Vite dev server 提供，才能用 `preview_screenshot` 看。

## 它給人的感覺（先講這個）

**一句話：它賣的不是記帳，是「被照顧」。** 功能清單解釋不了它為什麼好用；下面是它用什麼手法造出那個感覺，以及我量到的證據。

### 一、光與色：紙感、暖、只有一種色相

`voice-multi` 結束格（1180×2556，乾淨畫面）逐 pixel 統計：

| 量測 | 值 | 意思 |
| --- | --- | --- |
| 平均亮度 | **0.856** | 畫面 86% 是亮的——這是「晨光下的紙」，不是財務軟體 |
| 飽和像素的平均色相 | **31°** | **整頁只有一個色相家族**（琥珀／沙）；沒有藍、沒有紫 |
| 主要色票 | `#f0f0e0`(30%)、`#f0f0f0`(18%)、`#f0e0e0`(18%) | 奶油底＋更白的卡（卡比底更亮 → 卡片「浮起來」） |
| 暖色漸層佔比 | 約 15%（`#e0c0a0`／`#e0d0c0`／`#d0a080`） | 那片沙丘漸層不是裝飾，是畫面第二大面積的元素 |
| 純黑 | **1.8%**（＋近黑 1.7%） | 黑色是**保留色**：只給「主要動作」（抬升麥克風）與「當前選中」 |

對照我們：`--brand: #2f5d50` → 色相 **163°（冷綠）**；預設主題是 **dark**（`DEFAULT_THEME_MODE = "dark"`），畫面平均亮度約 0.1。

**關鍵發現：我們的淺色主題其實已經是同一個暖家族** —— `--bg-page: #f5f2ec`、`--bg-surface: #fffdf8`、`--text-primary: #242321`，跟他們的 `#f0f0ee` / `#f9f7f3` 幾乎同一個紙感。所以拉開差距的**不是色票，是預設值與 accent 色相**：一開就是深色工具、強調色是冷綠。這兩件事比任何新功能都更決定「第一眼像不像它」。

### 二、一個畫面只有一個主角

- Today：`今日` → **NT$415**（全畫面最大字，約行標題的 2 倍）→ 其餘一律小字。
- 報告頁最大數字是**淨額**，不是支出、也不是筆數。

手法是「**只留一個大字，其他全部退到小字**」。眼睛不需要讀，一眼就知道這頁在講什麼。我們的分幣別小計是 12px——那個數字在畫面上沒有重量。

### 三、姿態：少動手、不打擾、看得見它在幫你

- **每個分類有色點／圖示磚／淡色底** → 清單像**圖畫**而不是**表格**；使用者靠顏色記憶，不是靠文字。
- **中央抬升的黑色麥克風** → 主要動作是**身體動作**，永遠在拇指底下，不用進某一頁。
- **錄音時整張畫面模糊** → 一個很強的訊號：「你正在說話，其他都不重要」。連 `/support` 的**影片封面都刻意選這個模糊瞬間**。
- **說完立刻插一列、標題是原始語句、副標「分類中…」、金額先空著** → 先落地後補欄位。它不只用「不用打字」證明自己，還**把正在幫你做的事演出來**。
- **寬鬆列高、大圓角、浮動膠囊分頁列** → 從容、不急、單手可用。
- **膠囊式分段控制**（週／月、長條／圓餅）→ 選項少到不用思考。

### 四、語氣：一對一的關係，不是客服

「晚安 ☾」的問候、超支用 ⓘ 提醒而不是責備、「許願成功，謝謝你！」的 toast、許願池明說「還要 300 位會員就開發」（把 roadmap 變成可追蹤的承諾）、公告像人寫的信——**甚至為一段寫錯的說明道歉**。首月 Premium 自動開、不用密碼、CSV 可進可出、文案反覆強調「不用…」。

### 五、最刺的一段：這個「感覺」和我們現在的方向是相反的

我們這幾輪在做的是**讓一列承擔更多**：7 個欄位、三個版面級別、日期欄、兩個動作、精確的截斷契約——那是**準確**。
它的感覺來自**每列只承擔三件事**（品項／分類／金額＋時間），**日期交給頁面／月曆**。

兩者不能同時成立在同一列上。所以如果「那個感覺」是目標，該動的是**取捨**（日期要不要留在列上、動作要不要留在列上、商家／帳戶要不要留在列上），而不是再往列上疊東西。

### 我感覺不到的部分

我只有**靜態格**。這個 app 的感覺有很大一塊來自**動態與回饋**：按住時的動畫、放開的震動與音效、新列落地時的彈跳。他們的文案自己說「記帳快到有點爽」——那個「爽」我無法從截圖裡感受到，只能說它的**靜態姿勢已經在為那個爽鋪路**（所有東西都退開、只留一個動作）。

## 觀察到的畫面

### 1. Today（今日）— 核心畫面

`voice-multi` 結束格、`voice-basic` 6.5s、`voice-recurring` 結束格。

```
晚安 ☾                                    (+)
週一, 7月27日
┌────────────────────────────────────────┐
│ 今日                        ◯ 進度環  │
│ NT$415                               │
│ 4 筆支出                             │
│ 每月預算 75%              NT$12,368  │
│ ▬▬▬▬▬▬▬▬▬▬▬▬▬▬░░░░░░               │
│ 每週預算 0%               NT$2,000 > │
│ ░░░░░░░░░░░░░░░░░░░░               │
│ ⓘ 餐飲 · 超支 NT$5,885               │
└────────────────────────────────────────┘
(全部)(餐飲)(交通)(居家)(人情世故)      ← 每顆都帶分類色點
收支項目
┌────────────────────────────────────────┐
│ ▨ 停車費                        NT$30 │
│   交通                        5:08 PM │
└────────────────────────────────────────┘
```

- **頁首是日期**（上面還有一行問候語「晚安」／「午安」），日期在**頁面層級**。
- 主卡：`今日` → **當日總額（全畫面最大字，約行標題的 2 倍）** → `N 筆支出` →
  **預算列（百分比靠左、金額靠右、下方一條滿寬進度條）** → **超支提示列**（警示色＋
  ⓘ 圖示）。右上角是一個**進度環**，顏色／弧長隨預算狀態變（未設預算時是空灰環）。
- **分類 chips**：一顆代表一個分類使用過的分類，左側帶該分類的色點；選中者是黑底白字。
- **記錄列**：左邊一個**分類圖示磚**（約 44px 圓角方塊、該分類的淡色底＋專屬 glyph，
  例如 交通＝公車、餐飲＝刀叉、居家＝浴缸、人情世故＝單據），中間兩行
  （**品項粗體** ／ 分類小字），右邊兩行（**金額粗體** ／ 時間小字）。**沒有日期**。
- 有來源時分類行變成 `餐飲 · ▮手機條碼`（分類＋來源徽章，用 `·` 串接）。

### 2. 語音：按下→說→落地（`voice-basic`）

| 時間點 | 畫面 |
| --- | --- |
| 3.0s（聽音中） | 背景**整片模糊**，中央一行提示「請說出您的花費，例如: 早餐 70 元」，底部兩顆膠囊「✕ 取消」／「✓ 完成」 |
| 6.5s（落地） | 回到 Today，清單最上方**立刻多一列**：標題是**原始語句**「午餐 150」、副標「**分類中…**」、右側只有時間、**金額欄還沒有數字**；圖示磚是灰色佔位 |

- 這是整個產品的核心手感：**先落地、後補欄位**（optimistic insert），並用「分類中…」
  明說它還在解析，而不是留一個空白欄位。
- 同一格裡「今日」還是 `NT$0`、但已顯示「1 筆支出」——總額與筆數在解析完成前不同步，
  看得出總額是等解析後才算的。

### 3. 歷史（`history-backfill`）

- 標題列：`2026年7月 ⌄` ＋ 右側三顆小圓鈕（清單檢視／**月曆檢視**／`+`）。
- **整月月曆**：每格日期下方有記錄時帶一個**小色點**；今天＝實心黑圓；沒記錄的日期淡化。
- 月曆下方是**當日摘要帶**：`1 筆支出`（左）／`NT$50`（右），底色是一條淺米色橫帶。
- 再下面才是該日記錄列（同 Today 的列）。
- → **日期由月曆／摘要帶承擔，列上不需要日期欄。**

### 4. 報告（`reports-range`）

```
報告                    [週 | 月 | ▤ ]
        ( 📅 7/2 – 7/14 )
┌──────────────────────────────┐
│ 淨額                        │
│ NT$9,345                    │
│ 7月2日 – 7月14日            │
└──────────────────────────────┘
各類別支出        [長條圖 | 圓餅圖]
┌──────────────────────────────┐
│ 51.1%  37.8%  10.8%  0.3%   │
│  ▮      ▮      ▮      ▬     │
│ 購物   餐飲  美容美髮 交通  │
└──────────────────────────────┘
支出排行
┌──────────────────────────────┐
│ 1 ● 購物            NT$4,779 │
│                        51.1% │
│ 2 ● 餐飲            NT$3,533 │
│                        37.8% │
└──────────────────────────────┘
```

- H1 `報告` 右側是**三段式切換**（週／月／自訂）；期間以**膠囊**呈現（📅 + `7/2 – 7/14`）。
- 最大數字是**淨額**，不是支出、也不是筆數。
- 圖表切換是**膠囊式分頁**（長條圖／圓餅圖），不是下拉。
- 排行列：`名次 ● 分類`（左）／`金額`（右，粗體）＋`百分比`（右，小字）。

### 5. 設定（`bug-report` 結束格）

- 一頁到底的**分區卡片**堆疊，每個分區上方一行小字標題（`資料`／`社群`／`帳號`）。
- 每列＝**彩色圖示磚**（依項目給不同淡色底：紫／琥珀／粉／灰／藍）＋標籤＋右側 `>`。
- `社群` 分區放的是 `許願池`／`回報問題`／`支援`。
- `帳號` 分區：`登出`、**`刪除帳號`（紅字＋紅圖示）**。
- 最底部還有一列 `Debug Tools`（dev build 才有的入口）。

### 6. 公告（`announcement` 4.0s）

- 由底部升起的**卡片式 sheet**，蓋在 Today 上（後面那頁變暗但仍可見）。
- sheet 標題 `公告` ＋ 數量膠囊 `2 則`。
- 一則＝一張白卡：`2026 · 7月19日`（小字）→ **粗體標題** → 段落 →（可選）
  **內嵌宣傳圖** → `了解更多 →`（琥珀色連結）。

### 7. 許願池（`wish-pool`）

- 標題列：`←` ＋ `許願池` ＋ 右側 `+`。
- 操作後出現**浮動 toast**「✅ 許願成功，謝謝你！」（半透明膠囊、置頂、自動消失）。
- 已投票的想法：卡片標題＋說明＋右側**👍 票數藥丸**（圖示在上、數字在下）。
- `進行中` 分區：每張卡＝標題＋說明＋**滿寬細進度條**＋左 `2 / 300 位會員`＋右 `0%`。
  → 用「還要多少人連署才開發」當動機，把許願池變成可追蹤的承諾。

### ★ 日期進頁面，列就少一欄

競品的列之所以能只有三欄，是因為**日期由頁首／月曆承擔**。我們的列在 262px 下要把
金額移到第三列（見 [ledger-row-compact-plan.md](ledger-row-compact-plan.md) §3.4），
固定成本之一就是每列的日期欄：**39px ＋ 兩側 gap＝51px**。若改成依日分組、日期升為
群組標題，這 51px 會還給品項與帳戶·類別（推估 262px 下品項可由 158px 增至約 200px），
**有機會用兩列取代三列**。但這會動到已定案的類型分區與篩選，屬需先決策的結構變更。

## 交互特殊模式

以下模式比「功能有什麼」更值得看——它們是構成「被照顧」感覺的手法。

### Dynamic Island 是錄音的主介面

錄音時**不是另開頁面**，而是用 Dynamic Island 做為控制器：
- 紅點（錄音中）→ 波形（偵測語音）→ 方形停止鈕（即將結束）。
- 整頁模糊是背景，不遮蔽資訊——你隨時看得見之前的記錄。
- 這是**最少介入的錄音 UI**：不跳頁、不彈窗、不遮擋，只在頂部一條藥丸裡告诉你「我在聽」。

### 「先放下、後分類」的節奏（optimistic insert）

語音結果不是「處理完才顯示」，而是：
1. 先插一列（標題=原始語句，副標=「分類中...」，金額欄空著）。
2. AI 跑完後，列的標題、分類、金額**原地更新**（不是替換整列）。
3. 篩選膠囊在分類完成後**自動浮出**。

→ 使用者在 1-2 秒內就看到「它聽到了什麼」，而不是盯著 spinner 等 3-5 秒。這是「先讓你看見，再幫你處理」的節奏。

### 篩選膠囊是「自動浮出」的的漸進式揭露

篩選膠囊（全部/餐飲/交通/...）**不是預設就有的 UI 元素**，而是「有分類才需要篩選」——第一次語音記帳完成後才出現在清單上方。每顆膠囊帶該分類的色點，選中者是黑底白字。

### 兩階段分類（AI 先猜、未知的才問）

`voice-newcat` 的完整流程：
1. 語音結束後，AI **先把已知的分類套上去**（紅包 → 其他）。
2. 同時偵測到語句裡有**不在清單裡的新詞**（人情世故）。
3. 先插一列、標題是原始語句、「分類中…」。
4. 彈出**底部卡片**：「新增分類？— 點一下可改名與換色，左滑略過（改用「其他」）。」
5. 用戶可以「全部加入」或「略過」→ 列的分類即時更新。
6. 若選展開：**名稱可改、圖示 24 個可選、顏色 16 色可選**（全部都是暖色調，AI 也會根據語意預選）。

→ **AI 在猜到的那一刻就幫你做了，只把猜不準的那個才問你。** 這是「先做後問」而非「先問後做」。

### 懸浮文字提示內建手勢教學

新增分類卡片的說明：「點一下可改名與換色，**左滑略過**（改用「其他」）」。

→ 不是「使用說明頁」，而是在**需要的那一刻**教這個手勢。同時提供了**逃生出口**（略過＝不做這件事）。

### 固定收支建表（先呈現數字，再問週期）

`voice-recurring` 詳情卡：頂端是**巨大的金額**（NT$ 15,000，字級約 4x 行高），下方是說明欄、分類選擇格（彩色圖示磚網格），底部是週期選擇（每月／每週＋日期選擇器）。

→ 金額是這張卡的**唯一主角**。先看到數字、確認沒聽錯，再往下滑設定週期。分類格用**彩色圖示磚**（~44px 圓角方塊、淡色底、專屬 glyph），不是純文字列表——「居家」比「交通」更容易被眼球捕捉。

### 數字永遠是卡裡最大的字（敘事結構）

不管是 Today 的 `NT$415`、固定收支的 `NT$ 15,000`、報告的 `NT$9,345`，或歷史摘要的 `NT$50`——**金額永遠比其他文字大 2 倍以上**。名稱、時間、分類全部退到小字。

→ 這不是「字級差異」，是**敘事結構**：每一張卡都在說「這個數字最重要」。

### 「其他」是一個安全網

每一個分類操作都提供 escape hatch：新增分類可以「略過（改用「其他」）」、AI 分不清的就暫時放「其他」。沒有什麼非做不可的決定。

### 應用內回報：透明度即信任

`bug-report` 回報表單底部有**資料揭露聲明**（shield 圖示）：「將自動附上裝置資訊（iPhone · iOS 26.5.2 · v1.3.0）與匿名診斷紀錄（不含任何個人內容），僅用於協助排查問題。」placeholder 是「例如：點下記錄按鈕後 App 直接關閉」——**用一個真實 bug report 教你怎麼寫**。

### 月曆承擔日期，列就不需要日期欄

`history-backfill` 顯示整月月曆（每格日期下方有記錄時帶小色點，今天=實心黑圓），月曆下方是日摘要帶（`1 筆支出 NT$50`），再下面是該日記錄列。

→ **日期由月曆／摘要帶承擔，列上不需要日期欄。** 這就是他們的列能只有三欄的根本原因。對照我們：每列背日期欄的固定成本是 39px＋兩側 gap＝51px（262px 寬度下）。

### 報表的 hero 數字是「淨額」

報告頁最大數字是**淨額**（收入減支出），不是支出總額。切換用**膠囊式分段控制**（週/月/自訂），圖表切換也是膠囊（長條圖/圓餅圖）。日期範圍以膠囊呈現（📅 + `7/2 – 7/14`）。

### 問候語依時段切換

`voice-basic` 開頭是「午安」，`voice-multi` 和其他影片是「晚安」。日期固定格式是「週一, 7月27日」。這是小細節但增加了「一對一」的感覺。

### 這條時序在講什麼

**順序是：身分 → 回顧 → 自動化 → 擴張 → 協作 → 精確 → 資產。**

1. **v1.0 先把「怎麼記」定義完**（語音＋小工具），報表只是附帶。
2. **v1.1 立刻補「怎麼看」**（歷史改版、月曆）——因為記進去的下一步就是想看回來。
3. **v1.2 做自動化**（固定收支）——把記帳從「每次都要做」變成「一次就好」。
4. **v1.4 才做容器與上限**（多帳本、預算）——**注意：預算是第 4 版才出現的**。
5. **v1.5 做協作**（提醒、共用、雙向回報）。
6. **v1.6 做精確度**（支付方式、篩選、滑動補記）。
7. **v1.7 最後才做資產層**（餘額走勢、轉帳、資產調整歷史）。

## FAQ 回答了我們「看不到的畫面」

有三個我在逐幀分析裡標成「缺畫面」的問題，**官方文字已經回答**（不必等截圖）：

1. **點一筆之後怎麼改？** → 支援頁原文：「想改任何欄位，**點那筆帳打開編輯就好**」。
   → **編輯頁存在**，而且是全欄位編輯的入口。
2. **補記的日期是怎麼確認的？** → 「切到『歷史』頁、**先選好某一天**，再用語音或手動新增，
   那筆帳就會記在你選的那天。」
   → 機制是 **「先選日期，再新增」**：日期是**上下文**，不是表單欄位。這正好和明細頁那條
   「日期進頁面、不進列」是同一套設計語言。
3. **語音講到不存在的新分類會怎樣？** → 需要 `設定 →「自動建立分類」`（**預設已開**）。
   → 這是一個我沒看到的設定項，也是「AI 先做、再問你」那個流程的**開關**。

另外官方自己列出的當期 bug（`/known-issues`）就是 **v1.6.0 那個新分類流程的破口**：
「新增分類之後，剛剛那筆不會自動歸進新分類，會先被放在『其他』」——
**對照：我在 `voice-newcat` 逐幀時看到 AI 先用「其他」墊著，那是刻意的；但確認之後沒改回新分類是 bug。**
這證明「先放下、後分類」這個手感是有代價的：**狀態要能回頭收斂**。

## 「簡潔明瞭」是怎麼量出來的

「風格很簡潔」不是形容詞，它由四個**可測量**的規則構成。下面每一格都是本輪實測：

- **他們**：海報／影片逐幀（`reports-range` 海報做 ink-row 投影分析，592px ÷ 1.5 ＝ pt）。
- **我們**：跑起來的 app（viewer 實測 **361×631**），用 `preview_evaluate` 抽
  每個可見文字節點的字級／字重／顏色／Ｙ坐標，以及所有可互動控制項。

### 規則一：頭皮以上不得有東西（內容要到得早）

| 畫面 | 第一個「你來看的東西」出現的位置 |
| --- | --- |
| 念帳 `報告` | `淨額` hero 在 **y=321 / 1280 ＝ 25%**；上面只有 `報告`＋分段控制＋月份：**3 個元素** |
| 念帳 `Today` | 卡片就在問候語＋日期正下方：**2 行** |
| 我們 `明細` | 第一列在 **y=418 / 631 ＝ 66%**；它前面有 **14 個文字元素** |
| 我們 `概覽` | 第一張帳戶卡在 y=91 ＝ **14%** | ✅ 這頁合格 |

**66% 是這條規則的違反量。** 使用者要滑／瞄到 2/3 以下才看到第一筆帳。

### 規則二：同一個數字只能印一次

`概覽` 實測：**30 個文字節點、186 個字、其中 10 個是金額字串——但畫面上只有 2 個帳戶、4 個相異金額。**

```
重複字串：
  TWD -1,239,887   × 3
  TWD 5,000        × 3
  Daily wallet     × 2     新儲蓄戶   × 2
  餘額             × 2     淨支出     × 2     現金流   × 2
```

原因很具體：**同一批帳戶在一頁裡被畫了兩次**——先是 y=91～288 的帳戶卡，然後 y=396～704 的
`帳戶報表` 又把**相同的三個指標（餘額／淨支出／現金流）**再列一遍，只多了一個「TWD · N 筆記錄」。

**但要誠實說一個反例**：他們的報告頁也重複，**百分比在長條圖上方與支出排行各出現一次**。
差別是：他們的重複是**交叉參照**（同一個百分比把圖和排行綁在一起，是連結），
我們的重複是**同一張卡印兩次**，不增加任何資訊。

### 規則三：列上不放動作

| | 每列的可點目標 |
| --- | --- |
| 念帳 | **0 個**。列＝圖示磚＋品項／分類＋金額／時間；支援頁原文：「想改任何欄位，**點那筆帳打開編輯就好**」 |
| 我們 `明細` | **每列 2 個**（`編輯`、`作廢`）。3 筆帳的畫面上總共 **18 個可互動控制項**，其中 **6 個**是列動作 |

這條直接跟前面量到的另一個問題接上：**我們圖示操作區只有 22×22px，而計畫要求 44×44px。**
如果列上根本沒有動作，那兩個小按鈕就不存在，**也就不需要把它們放大**——
不是把它們變大，是把它們拿走。

### 規則四：重複的狀態要提上去，不要貼在每一列

- 我們：`僅本機` 徽章在 3 列上各出現一次（3 個重複狀態）。
- 他們：預算超支這種全域狀態是**一列頁級提示**（`ⓘ 餐飲 · 超支 NT$5,885`），不是貼在每一筆帳上。

### 規則五：標籤要短

- 我們 `明細`：平均 **7.4 個字**／標籤；最長的幾個：`排序: 日期（新 → 舊）`、`2 筆 · 小計 TWD 1,234,887`。
- 他們：主要標籤都是 **2～5 字**（`淨額`／`今日`／`報告`／`各類別支出`／`支出排行`／`長條圖`／`圓餅圖`），
  沒有任何標籤帶冒號、括號或箭頭。

### 誠實的例外：字級數量我們並沒有比較差

這條值得單獨講，因為它推翻了一個直覺。拿同一種方法量：

| | 量到的字級層 |
| --- | --- |
| 念帳 `報告` 海報 | ink-row 聚成 **6 層**（約 7 / 9 / 11 / 15 / 21 / 25 pt） |
| 我們 `明細` | **7 層**（11 / 12 / 13 / 14 / 16 / 18 / 26px） |
| 我們 `概覽` | **8 層**（11 / 12 / 13 / 14 / 16 / 18 / 22 / 26px） |

**差別不是字級，是元素數與重複。**
這也解釋了一件已經發生的事：前面幾輪把明細列的字級提到 14/16px，
**畫面並沒有因此變簡潔**——因為「不簡潔」的來源不在字級上。

### 所以「簡潔明瞭」的一輪該動什麼（按效果排序）

| 動作 | 省下什麼（可量測） | 風險 |

## 觀察紀律

- 「畫面事實」與「我的推論」分開；推論要能被下一格畫面證實或推翻。
- 尺寸用**比例**描述（相對行標題幾倍），因為原始素材是 3× 螢幕截圖；要精確值就回到
  1180×2556 的原圖量（÷3＝pt）。
- 「他們有、我們沒有」**先查證再寫**（預算／公告／許願／回報／支付／圖表／資產／多帳本都 grep 過 `src/` 才寫的）。
- **不要把「我的工具抽不到」寫成「那裡沒有」**（本文件最初犯過的錯）：`read_url` 只給文字，
  所以「文字抽不到圖」≠「頁面沒有 UI」。**能看得見的東西就去看，不要用工具限制下結論。**
- **不要假設一個頁面的 HTML 就是它的全部內容**：`/release-notes` 的 HTML 只有空殼，
  9 版內容全靠 `fetch('/releases')`。遇到「讀起來很薄」的頁面，先找它呼叫了哪支 API。
- 「官方文字」與「畫面觀察」**在表格裡要分開標**：文字能證實「存在」，但不能證實「長什麼樣」。
- 官方自己公開的 bug（`/known-issues`）**比任何畫面都値錢**：它直接指出那套手感的代價在哪。
