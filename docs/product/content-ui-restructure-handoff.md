# 各頁內容 UI 重整：實作交接規劃

日期：2026-09-13  
狀態：待實作與驗收。這是一份交接規格，不是完成報告。  
範圍：MealLedger 既有應用的各頁內容，不重做導覽、不重建應用。

## 1. 給接手 AI 的第一條指令

請先閱讀本文件、檢查目前工作區差異、啟動現有應用並逐頁看實際畫面，再實作。不能只按檔案中的 CSS 數值推測 UI 已經合理。

使用者認為現在的問題是「亂」，不是單純不夠漂亮：重複資訊、位置不固定、操作互相分離、各頁對齊規則不同，使人難以找到資訊與完成操作。修正必須改變內容組織；只縮卡片、置中表單、調 tab 樣式或換顏色，不算完成。

本文件已包含實作方向，不需再次交一份只有概念的提案。先完成概覽與明細的整體結構，實際檢視，再繼續其他頁。保留功能，不用移除功能來換取簡潔。

## 2. 不可越過的邊界

- 沿用目前主導覽、路由與 Settings 分頁。桌面 Settings 保留左下角；不重開「帳號應放哪裡」的討論。
- 保留本機優先工作區。未登入、無帳戶也能進入，不新增強制 onboarding gate。
- 保留帳務計算、記錄分組、篩選、初始資金、負餘額政策、作廢與真正刪除的既有語意。
- 保留 email/password 登入與註冊、確認密碼、顯示密碼、Google、Facebook、忘記密碼、密碼重設、身分連結管理與 handoff。
- 登入成功不等於使用者同意交接資料，也不等於同步成功。未確認 handoff 不得 claim 或 enqueue 雲端同步。
- 保留整段口說、逐欄口說、辨識結果編輯、AI 帳戶／類別政策及確認寫入流程。
- 保留六種專區工具、圖片預覽、保留／捨棄、上傳狀態與清理操作。
- 不改公開 API、持久化資料格式、Schema、Supabase persistence API，不新增 migration。
- 不新增 UI 框架，不整份重寫 App，不以全域 CSS 強制壓平所有不同類型的控制項。
- 不重設或清空使用者資料，不用真實帳號、真實麥克風或真實雲端同步製造測試資料。
- 保留所有既有未提交修改；禁止用 checkout/reset 還原來取得乾淨基底。
- 本任務不 push、不開 PR、不重寫提交歷史；提交需另獲授權。
- 不開子 agent，除非使用者另外要求。

## 5. 共用布局契約

### 5.1 頁面骨架與對齊

1. 保留一個頁面 H1。頁面主操作可以放在同一列右側；手機可換到下一列。
2. 主內容緊接標題，不再插入相同意思的 eyebrow、第二個頁名或正常狀態長條。
3. 內容以左側共同基準線排列。Settings 每個分頁的第一個內容區，左邊界與分頁列左邊界一致。
4. 一般內容上限 1120px；一般表單上限 640px；帳號驗證表單上限 440px。上限指內容寬度，不包含 sidebar。
5. 不把所有頁面套成同一個 440px 或 640px 置中框。列表與報表使用可用寬度，表單使用舒適寬度。
6. 新增頁的 640px 操作區也從內容共同起點開始；模式切換與其內文對齊，不再掛在遠端頁頭。
7. 窄表單右側留白可以存在，不用無關說明或裝飾卡填滿；關鍵是標題、欄位與按鈕屬於同一組，不孤立漂浮。

### 5.2 尺寸與樣式

| 元素 | 規格 |
| --- | --- |
| 內文、輸入 | 16px，不以 viewport width 縮放字體 |
| 輔助資訊 | 14px，不能為塞下資料降到難讀的小字 |
| H1 | 桌面約 28–32px，手機約 24–28px，不採 hero 尺寸 |
| 區段標題 | 約 18–20px，不每個小控制都加標題 |
| 主要按鈕、輸入 | 至少 44px 高；標準單行可固定 44px |
| 圖示操作 | 可見圖示約 18–20px，觸控區至少 44×44px |
| 間距 | 欄位內 8px、相關欄位 12–16px、區段 24px；不靠空 flex 填滿高度 |
| 手機左右留白 | 16px，320px 下仍適用 |
| 圓角 | 不超過 8px，除原有語音圓形操作與品牌資產 |

頁面區段用留白與必要分隔線，不用浮動大卡片。卡片僅留給重複資料項、必要框定工具或既有合理 dialog。不做卡片套卡片，不加裝飾漸層或陰影補救結構。

深／淺色均使用既有 theme tokens。正常次要文案不全部標成警告色。一般文字對比目標至少 4.5:1；控制邊界與 focus 指示須可辨識。這是待量測目標，不是目前已達標的聲明。

### 5.3 響應式與狀態

- 桌面先建立穩定欄位，手機重排為清楚的讀取順序，不只是縮字。
- 可變長名稱允許折行或省略，但必須有可用鍵盤／點擊檢視完整值的方法；金額、幣別與操作不可省略。
- 不以 body 或主工作區 `overflow: hidden` 遮掉溢位；不得裁切鍵盤開啟後的輸入／提交。
- 主內容不固定展示 Local-only、沒有草稿等正常狀態。保留既有帳號／導覽狀態來源，不再新增第二份。
- 錯誤靠近出錯欄位或操作；成功訊息屬於本次操作，不能由歷史記錄數推導。
- 儲存中停用會重複提交的操作，保留輸入；錯誤時可重試，不清空表單。

## 6. 概覽：單一帳戶總覽

### 有帳戶

桌面結構：

```text
概覽                                      [新增帳戶]

帳戶／幣別       餘額       期初餘額       淨支出       現金流
帳戶 A / TWD     ...        ...            ...          ...
帳戶 B / USD     ...        ...            ...          ...

[僅發生同步失敗時：錯誤摘要與重試]
```

- 移除現在上方每帳戶餘額摘要卡，將同一資料合併進報表，不保留兩份餘額。
- 使用既有 accountReports／calculateAccountBalances 的值，不自行加減推導新的報表語意。
- 固定每個帳戶都有相同欄位。沒有期初資金時以既有模型確認的 0 顯示；若語意是不可用則顯示「—」，不能直接移除欄位。
- 不同幣別各自格式化，不相加，不新增沒有匯率依據的總資產。
- 桌面同一數值欄右對齊，使用 tabular-nums；貨幣代碼與數字保持一組。
- 有帳戶但沒有交易仍顯示零值、一次簡短「尚無交易」狀態與建立記錄入口。
- 768px 欄寬不足時就採手機式布局，不硬撐五欄。

手機：每帳戶一個資料項，先顯示名称／幣別，下面四個指標固定兩欄，順序為餘額、期初、淨支出、現金流。不因有無某類交易改變指標位置。

### 無帳戶

只顯示一個起始區：「建立第一個帳戶」及單一 CTA。點擊開啟既有帳戶建立流程，完成回到可用總覽。不得再出現報表空卡、零個帳戶摘要與另一個首次設定按鈕。

### 驗收

- 相同幣別欄位可直向比較；不同幣別不混總。
- 0、1、多帳戶都沒有重複摘要。
- 長名稱不推擠金額；手機四個指標位置一致。

## 7. 明細：記錄優先

```text
明細  ·  N 筆                              [新增記錄]
搜尋                  帳戶／類別／來源／排序

支出                         分幣別小計
日期  名稱／品項  帳戶·類別             金額  編輯  作廢
...

待審 N 筆（僅有資料時）
草稿資料                         編輯／確認／捨棄
```

- 頁面 H1 之外不再新增「明細記錄」「已確認記錄」「明細歷史」連續標題。記錄數與新增操作可透過既有頁頭呈現，不以重複 H2 模擬工具列。
- 保留搜尋、帳戶快篩、類別、商家／來源、排序及既有分組。不為變薄而刪篩選器。
- 篩選區使用一般背景與緊密間距，移除包住全組的厚重卡片。手機搜尋獨占第一列，其他篩選自然換行。
- 記錄主資訊為品項／名稱與金額；日期、商家、帳戶及類別為次要資訊，但保持可讀。
- 桌面用穩定 grid tracks，不靠空白字元或 margin 猜對齊。窄版先保留日期、名稱、金額和動作，再將 metadata 排第二列。
- 保留編輯、作廢／刪除、復發與缺漏資料處理入口。兩種刪除不可共用誤導文案。
- `[missing:app.recordTransfer]` 要追查 translation key，補中英文及回歸测试，不用 CSS 隱藏或把所有轉帳改成空標題。
- 分組小計仍按幣別顯示，多幣別摘要允許換行，不 ellipsis 掉整種幣別。
- 全域無記錄：一個空狀態與新增 CTA。篩選後無結果：保留篩選與清除入口，文案說「無符合結果」，不得誤稱沒有任何記錄。
- 沒有草稿完全不渲染待審空卡；有草稿時各既有操作完整可達。

## 8. 新增：連續的語音操作區

頁面標題下，一個最大 640px 的未框定操作區。整段與逐欄模式共用外層起點，不在 viewport 遠右角掛切換器。

逐欄順序：

```text
[整段口說 | 逐欄口說]
第 N 步／共 N 步 + 進度
目前欄位名稱 + 一句有效示例
[麥克風]
辨識中／辨識結果
可編輯的校對欄位
[重新說]                         [填入此欄]
```

- 麥克風固定約 96px 圓形；狀態環不得以整個父容器尺寸變成橢圓。
- 區段間距 16–24px，不用 flex:1、min-height:100vh 或 space-between 把內容拆開。
- 保留必要的欄位指引，移除解釋「欄位會亮起、AI 會校對」等實作式冗長開場。
- 辨識結果、可編輯欄位與確認操作相鄰。訊息出現時允許自然長高，不裁切。
- 整段模式同樣為模式、輸入／麥克風、辨識結果、可編輯草稿、確認；保持現有多筆辨識與逐筆處理能力。
- 最後寫入前仍按現有流程驗證所有欄位；AI 提供結果不是自動確認寫入。
- 麥克風未授權、不支援、辨識失敗、網路錯誤時有就近提示及既有可用替代輸入，不陷入不可退出狀態。
- 手機開啟鍵盤後可捲到目前欄位和確認，fixed 導覽不得遮住最後一行。

## 9. 專區：所選工具就是主體

- 六種操作保留：手動明細、AI 補帳、掃描發票、掃描收據、記錄餐點、附加照片。
- 桌面 3 欄×2 列；手機 2 欄×3 列。六格同尺寸，名稱可合理折行，不讓某一格獨占第三列寬度。
- 頁面 H1 下直接放工具選擇；移除「快速記帳／你要記錄什麼」等重複開場層級。每個工具只留一個必要標題。
- 所選工具以下最多 640px 表單，與工具區左側對齊；一般桌面最多兩欄、手機一欄。
- 手動記錄沿用先選帳戶後顯示依賴欄位的邏輯。選帳戶後金額、帳戶是優先資訊，日期／類型／條件欄位保持合理順序。
- 不把正常「尚未選帳戶」畫成大面積黃色警告卡；用帳戶控制旁簡短提示。
- 刪除由 records.length 顯示的常駐「記錄已儲存」大卡。僅本次成功後顯示短訊息與必要「查看記錄」操作；切換工具或开始下一筆不留下假的完成狀態。
- 上傳工具保留縮圖、檔名、暫存／保留／已上傳／失敗狀態與清除。長檔名不能撑寬頁面。
- 捨棄全部圖片後，佇列數必須來自剩餘實際資料；不要用改文案掩蓋殘留佇列。若涉及本輪以外資料缺陷，獨立記錄並修正最小必要範圍。
- 掃描來源不自動產生正式明細，餐點／照片不混進乾淨帳務匯出。

## 10. 設定：同一內容起點，不同任務寬度

沿用帳號、資料、類別、相關設定四個分頁及現有命名。以下是分頁內部布局，不增設新導覽。

### 10.1 帳號：未登入

440px 單欄，靠內容共同左邊界；無外層寬卡，不另置中。順序：

1. 登入／建立帳號的切換。
2. Email。
3. Password；固定輸入框內的顯示密碼按鈕，文字預留空間。
4. 登入時，忘記密碼放在密碼正下方靠右。
5. 註冊時，確認密碼。
6. 全寬主要按鈕，動詞依模式為「登入／建立帳號」，不要只有「繼續」。
7. 簡短分隔文字。
8. 全寬 Google 按鈕。
9. 全寬 Facebook 按鈕。

官方圖示資產完整保留，不重畫。兩個 provider 各一列，文字不拆行。若 320px 的內距不足，先減多餘內距或使用既有核准的短文案，不縮字、去圖示、藏按鈕。

密碼重設與 recovery 沿用同一欄寬、對齊與錯誤位置，保留返回登入入口。未提交不得清除使用者輸入；切換模式只按既有安全語意清除必要欄位。

### 10.2 帳號：已登入

最大 640px，三個垂直區段，使用分隔線而非三個大卡：

| 區段 | 內容 |
| --- | --- |
| 身分 | 實際帳號識別、現有連結方式；不顯示登入表單，不在無資料時造一個假 email |
| 同步 | 未交接／可同步／同步中／已同步／排隊／失敗的真實狀態；錯誤可重試 |
| 操作 | 現有身分連結／解除限制、登出、相關必要操作；保留安全防護 |

待 handoff 才顯示 accounts、records、drafts、meals、media metadata 數量與確認／稍後操作。計數沿用既有邏輯，不能漏項或把「已登入」當成已同意。

「同步可用」表示有資格同步；「已同步」只在實際無待處理項目且完成同步時顯示。登出／session 過期回本機模式，本機資料可用，不顯示 synced。

### 10.3 資料

同一左邊界，最大 640px，兩個區段：

```text
匯出
[格式：CSV v] [匯出]
操作中／成功／失敗的就近訊息

-----------------------------
匯入
[選擇 CSV 檔案] 檔名
（選檔後才出現驗證與審核結果）
```

預設 CSV，可選 JSON／ZIP；選擇格式不立即下載，點匯出才執行。保持三種 serializer、ZIP 進度與失敗處理。不要新增資料格式。320px 可分兩列，但格式與按鈕仍緊鄰。

沒有選檔不顯示「尚未選檔／驗證不寫入」等多個空訊息區。選檔後保留 mapping、錯誤、預覽、確認與重複匯入處理。

### 10.4 類別

緊密列表，名稱、使用數、操作固定對齊。名稱可以伸縮，使用數和動作不可被擠掉。保留既有新增、改名、別名與刪除限制，不新增尚未存在的管理 API。新增與改名使用既有行內表單；錯誤跟著該列，不佔全頁卡片。

### 10.5 相關設定

- 第一段帳戶管理：顯示名稱、類型、幣別、餘額。數字右對齊，不在名稱那一行重複幣別兩次。
- 有帳戶先看列表與「新增帳戶」；點擊才展開表單，成功收起、失敗保留、取消不寫入。
- 無帳戶直接顯示一次建立表單，不再同時提供首次設定入口。
- 表單最多 640px，保留日期、初始資金、類型、幣別與負餘額驗證；主按鈕不隨旁邊 fieldset 撐成高方塊。
- 偏好置於管理段下方，以分隔線區分。每列桌面名稱約 180–220px、右側控制剩餘可用寬度，整組上限約 800px，不留過大的中間空洞。
- 手機名稱在上、控制在下；AI 偏好的多選項可逐項排列，不塞成橫向極長列。
- 一項設定只顯示一次名稱。可使用 visually-hidden legend 保留語意，不能為去重移除 accessible name。
- 沿用即時或明確儲存的現有機制，不新增沒有作用的儲存按鈕。重新載入後必須保留已選設定。

## 12. 實作順序與階段門檻

1. **基線盤點**：截取目前各頁桌面／手機，記錄 URL、viewport、語言、主題及測試資料，不先改 UI。

## 13. 驗收資料與視覺矩陣

所有測試使用獨立 context／測試 workspace，資料 seed 用既有 helpers，不改正式資料格式。

### 13.1 資料集

| 代號 | 內容 |
| --- | --- |
| D0 | 未登入、無帳戶、無記錄／草稿／媒體 |
| D1 | 一個零交易帳戶，餘額與期初按模型為 0 |
| D2 | 至少三帳戶，TWD／USD／JPY，含長中文與長英文名稱、小數、負數與大金額 |

| D5 | 未登入、登入失敗、註冊驗證錯誤、recovery、已登入未交接、同步可用、同步中、失敗、session 過期 |

### 13.2 必測尺寸

- 1440×900：桌面主構圖、固定報表欄、列表主次。
- 768×1024：中間寬度重排、不能落入兩端之間的壞布局。
- 390×844：手機完整操作與正常垂直捲動。
- 320×844：最窄寬度、長文字、provider 按鈕、金額、動作。

每一頁／設定分頁至少在四種尺寸各看一次；390 與 1440 至少覆蓋中／英文、深／淺色的四種組合。D2 長資料於四尺寸都測；D5 每狀態至少於桌面與手機測。空資料與有資料不能互相代替。

### 13.3 實際操作

- 建立第一帳戶、第二帳戶、取消、重名錯誤、初始資金與不允許負餘額。
- 新增與編輯記錄，確認計數、明細及餘額更新；轉帳不可重複記入。
- 搜尋、帳戶／類別／來源篩選、排序、清除篩選及無結果。
- 草稿編輯／確認／捨棄，媒體保留／清除與佇列狀態一致。
- CSV／JSON／ZIP 切換與實際下載，確認格式／副檔名及既有資料語意；無效 CSV 顯示錯誤，有效檔案可審核。
- 註冊欄位、密碼顯示、忘記密碼、recovery、兩個 OAuth 入口。自動測試 mock provider/session，不索取真實密碼。
- 驗證 handoff 前未 enqueue、確認後才 enqueue；登出後新增保持 local-only。
- 語音 mock 成功、錯誤、結果修改、重說、逐欄前進／最終確認；避免呼叫真實辨識服務。
- 主題、語言、刪除與 AI 偏好修改後重新載入仍保留；不更動使用者真實偏好做測試。
- 鍵盤 Tab 順序和可見 focus；顯示密碼／編輯／刪除圖示都有可讀名稱，觸控不只靠 hover。
